# **Отчет по фронтенду 10.07**

На текущем этапе была начата переработка фронтенд-части электронного журнала. Перед началом разработки я изучил документацию `API.md`, чтобы понимать, какие ручки уже запланированы и какие данные можно использовать на стороне интерфейса. Также был просмотрен текущий фронтенд проекта: его структура, существующие экраны, авторизация и общая организация компонентов.

После знакомства с текущей реализацией было принято решение не дорабатывать старый интерфейс точечно, а начать полноценную переработку фронтенда с нуля. При этом панель входа была оставлена как основа, потому что она уже выглядела достаточно неплохо и не требовала полного удаления. Основной акцент был сделан на переписывание внутреннего интерфейса после авторизации.

Для работы была создана отдельная ветка `fix_frontend`, чтобы изменения по новому интерфейсу не смешивались с основной веткой. Перед началом реализации был подготовлен примерный дизайн в Figma. Макет не является финальным и идеальным, он использовался как ориентир, от которого можно отталкиваться при разработке экранов.

## **Основные изменения**

### **Навигация**

Была переработана навигационная панель приложения. Вместо старого варианта сделана новая боковая панель с разделами личного кабинета:

- главная;
- расписание;
- оценки;
- посещаемость;
- аналитика;
- профиль.

Навигация стала визуально ближе к новому стилю интерфейса: появились отдельные иконки, активное состояние выбранного раздела, более аккуратные отступы и адаптивное поведение для небольших экранов.

### **Профиль пользователя**

Был добавлен экран профиля пользователя. В профиле отображаются основные данные студента:

- ФИО;
- группа;
- статус;
- логин;
- ID студента;
- email.

Также были добавлены вкладки внутри профиля:

- `Мой профиль`;
- `Безопасность`;
- `Уведомления`.

Во вкладке безопасности была подготовлена форма для привязки email. Во вкладке уведомлений сделаны базовые элементы будущих настроек уведомлений. Эти разделы пока являются частью интерфейсной заготовки и будут дорабатываться по мере готовности backend-логики.

### **Расписание**

Был добавлен отдельный экран расписания. При реализации учитывался дизайн, где расписание состоит из:

- переключателей режима отображения: `Неделя`, `День`, `Список`;
- списка пар на выбранный день;
- календаря справа;
- фильтров по предметам и преподавателям.

На текущем этапе рабочим источником данных является ручка:

```jsx
GET /api/student/schedule/day?date=YYYY-MM-DD
```

Эта ручка позволяет получать расписание студента на выбранный день в пределах текущей или следующей календарной недели. Поэтому основной рабочий режим сейчас — просмотр расписания по дням. Режимы `Неделя` и `Список` заложены в интерфейс как будущие представления тех же данных, но для полноценной работы по неделям и месяцам в дальнейшем потребуется отдельная backend-ручка на диапазон дат или месяц.

## **Коммиты**

В рамках работы были сделаны два основных коммита:

### **`3ce39ce Polish profile and navigation UI`**

В этом коммите была выполнена основная работа по новому внутреннему интерфейсу:

- переработана навигационная панель;
- оформлен экран профиля;
- добавлены вкладки профиля;
- подготовлены блоки безопасности и уведомлений;
- улучшена адаптивность интерфейса.

### **`3e7987d Add student schedule page`**

В этом коммите был добавлен экран расписания:

- создан компонент страницы расписания;
- подключен раздел расписания к навигации;
- добавлена работа с API расписания студента на день;
- реализованы календарь, список пар и базовые фильтры;
- добавлены стили и адаптивная верстка для экрана расписания.

## **Итог**

В результате была заложена основа нового фронтенда электронного журнала. Авторизация была сохранена, так как её текущий вариант можно использовать дальше, а основная внутренняя часть приложения начала переписываться заново. На данный момент готовы первые ключевые разделы нового интерфейса: навигация, профиль пользователя и расписание.

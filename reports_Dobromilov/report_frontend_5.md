# **Отчет по фронтенду 07.08**

## **Цели недели**

1. Добавить при регистрации обязательное согласие на обработку персональных данных.

2. Спроектировать формат JSON для формирования отчетов с учетом роли пользователя.

3. Реализовать XLSX-отчет для преподавателя.

4. Реализовать XLSX-отчет для заведующего кафедрой.

## **Выполненная работа**

### **Согласие на обработку персональных данных**

В форму регистрации была добавлена отдельная плашка с обязательным согласием на обработку персональных данных.

Реализованы:

- чекбокс согласия;
- запрет регистрации без установленного чекбокса;
- понятное сообщение о необходимости предоставить согласие;
- ссылка на PDF-документ с текстом согласия;
- открытие документа в отдельной вкладке;
- кнопка отзыва согласия в профиле пользователя.

Кнопка отзыва пока отключена, поскольку для завершения сценария требуется отдельная backend-ручка. Frontend-интерфейс для дальнейшего подключения уже подготовлен.

### **Ролевой формат данных для отчетов**

Был спроектирован единый JSON-контракт, на основе которого Python-скрипты могут формировать XLSX-файлы для разных ролей.

В тестовом наборе данных представлены:

- 3 учебные группы;
- 75 студентов;
- 8 предметов;
- оценки по 100-балльной шкале;
- лекции, лабораторные и практические занятия;
- предметная и общая посещаемость;
- наличие или отсутствие согласия на обработку персональных данных;
- связи предметов с преподавателями и кафедрами.

Для студентов, предоставивших согласие, в отчет передается ФИО. Если согласия нет, вместо ФИО используется стабильный SHA-256-хеш без передачи персональных данных.

Для преподавателя backend должен возвращать только его предметы и связанные с ними группы. Для заведующего кафедрой должны быть доступны выбранные предметы и группы только в пределах его кафедры.

В контракт были заложены следующие основные сущности:

```jsx
{
	"semester": {},
	"access_control": {},
	"departments": [],
	"subjects": [],
	"groups": []
}
```

Данные студента содержат идентификатор или хеш, состояние согласия и показатели по предметам. Для преподавательского отчета дополнительно передаются отдельные лекции, лабораторные и практики.

Реальная проверка роли должна выполняться backend по токену пользователя. Frontend и Python-скрипт не должны самостоятельно определять доступ пользователя к чужим предметам или кафедрам.

### **XLSX-отчет преподавателя**

Был реализован отдельный Python-скрипт `teacher_report.py`, создающий подробный отчет преподавателя по выбранному предмету.

Первый лист отчета содержит:

- номер студента;
- ФИО или анонимный хеш;
- группу;
- посещаемость каждой лекции;
- оценки за лабораторные работы;
- оценки за практические занятия;
- итоговую успеваемость по предмету;
- посещаемость по предмету.

Для лекций используются обозначения:

- пустая ячейка — студент присутствовал;
- `П` — пропуск занятия;
- `Б` — отсутствие по болезни со справкой.

Лабораторные и выставленные оценки за практики выводятся по 100-балльной шкале. Если оценка за практику еще не выставлена, соответствующая ячейка остается пустой.

На втором листе размещена аналитика по группам:

- средняя успеваемость;
- средняя посещаемость;
- сравнительные диаграммы по выбранному предмету.

Скрипт проверяет принадлежность предмета преподавателю. Попытка сформировать отчет по чужому предмету завершается отказом до создания XLSX-файла.

### **XLSX-отчет заведующего кафедрой**

Был реализован отдельный Python-скрипт `department_head_report.py` для формирования сводки по кафедре.

Первый лист содержит общую таблицу:

- номер студента;
- ФИО или анонимный хеш;
- группу;
- среднюю успеваемость по каждому выбранному предмету;
- итоговый показатель успеваемости;
- общую посещаемость.

Предметы представлены отдельными динамическими колонками. Значения выделяются цветом в зависимости от результата, что позволяет быстро находить сильные и проблемные показатели.

На втором листе формируются сравнительные графики:

- средняя успеваемость по предметам;
- итоговые показатели по группам;
- посещаемость по группам;
- распределение оценок студентов.

Заведующий может выбирать один, несколько или все предметы своей кафедры. Попытка запросить предмет другой кафедры блокируется.

## **Выполненная работа**

### **Аналитика студента**

Была добавлена отдельная страница `AnalyticsPage`, доступная студенту через раздел «Аналитика» в навигационной панели.

Для получения данных используются ручки:

```jsx
GET /api/student/performance/radar
GET /api/student/grades/all
```

На странице реализованы:

- переключение между успеваемостью и посещаемостью;
- многоугольная диаграмма по предметам;
- подписи предметов и проценты на вершинах диаграммы;
- количество предметов, участвующих в расчете;
- средний результат студента;
- определение лучшего предмета;
- расшифровка результатов в виде списка предметов и полос прогресса;
- состояния загрузки, ошибки и отсутствия данных;
- адаптивное отображение на разных размерах экрана.

При формировании аналитики используются только реальные предметы студента, полученные от backend.

Для построения полноценного многоугольника требуется минимум три предмета. Если данных меньше, интерфейс сообщает, сколько предметов доступно сейчас.

### **Посещаемость в аналитике**

Интерфейс аналитики уже содержит отдельный режим «Посещаемость». Он рассчитан на отображение процента посещаемости отдельно по каждому предмету так же как и аналитика успеваемости, но тут не хватает ручки, на созвоне ближайшем обсудим и добавим ручку для вывода дат.

### **Настройка 2FA в профиле**

Во вкладке «Безопасность» был разработан интерфейс управления двухфакторной аутентификацией.

Фронтенд подключен к следующим ручкам:

```jsx
GET  /api/user/2fa/generate
POST /api/user/2fa/verify
POST /api/user/2fa/disable
```

В интерфейсе реализованы:

- отображение текущего состояния 2FA;
- кнопка начала подключения;
- получение и отображение QR-кода;
- вывод секретного ключа для ручной настройки;
- копирование секретного ключа;
- ввод и проверка шестизначного одноразового кода;
- отключение 2FA с подтверждением действия;
- понятные сообщения об ошибках и успешных действиях.

Поддержка ввода 2FA-кода при авторизации была добавлена ранее и сохранена.

Полностью проверить подключение пока нельзя: ручка `GET /api/user/2fa/generate` возвращает ошибку `Error parsing body`. Фронтенд отправляет корректный GET-запрос без тела, но backend пытается разобрать отсутствующее JSON-тело.

Также ответ `/profile` должен возвращать поле `two_fa_enabled`, чтобы после обновления страницы фронтенд мог восстановить актуальное состояние 2FA. Беку информация передана, сказал устарнит момент.

### **Загрузка аватара**

Была доработана загрузка фотографии профиля.

Реализованы:

- выбор изображения через системное окно;
- поддержка JPEG, PNG и WebP;
- проверка типа и размера файла;
- центральная квадратная обрезка изображения;
- преобразование изображения в WebP перед загрузкой;
- уменьшение разрешения и размера файла;
- предварительный просмотр нового аватара;
- состояние загрузки и сообщения об ошибках;
- обновление аватара без перезагрузки страницы;
- корректное восстановление адреса изображения после повторной загрузки профиля.

Для отправки файла используется ручка:

```jsx
POST /api/user/upload-avatar
```

После исправлений загруженный аватар сохраняется на сервере и продолжает отображаться после обновления страницы.

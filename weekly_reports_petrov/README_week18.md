## Часть 1. Порядок в репозитории

Раньше backend и frontend лежали вперемешку в одной папке, плюс скопилось много старых файлов-бэкапов (`.bak`, `.backup`). Разложили всё по местам: отдельно `backend/`, отдельно `frontend/`, мусорные файлы удалили. Заодно поправили CI — после переезда файлов он не мог найти `package-lock.json` для кэширования зависимостей, добавили правильный путь.

## Часть 2. Новые возможности backend

### 2.1 Преподаватель может вручную поправить посещаемость

Раньше студент мог отметиться только сам (по ссылке/QR или через геолокацию в приложении). Если у студента не сработал GPS, разрядился телефон, или он отсутствовал по уважительной причине — исправить это было нельзя.

Добавили ручку `POST /api/teacher/attendance/mark`. Преподаватель выбирает своё занятие, студента и ставит один из статусов: **был**, **не был**, **опоздал**, **уважительная причина**. В базе данных эти статусы уже были заложены заранее, просто ими некому было пользоваться — теперь через API можно.

Проверки:
- нельзя поправить занятие чужого преподавателя
- нельзя поставить студента, которого нет в этой группе/занятии
- статус может быть только один из четырёх разрешённых, иначе ошибка с понятным текстом

Всё протестировано на живом стенде: и успешный случай, и все ошибки (чужая роль, чужое занятие, неверный статус, студент не найден, запрос без входа в систему).

### 2.2 Расписание студента на конкретный день

Добавили ручку `GET /api/student/schedule/day` — студент может посмотреть своё расписание на любой день текущей или следующей недели (просто передать дату, например `2026-07-06`). Если дату не указать — вернётся расписание на сегодня.

Ручка сама учитывает переход через выходные и то, что расписание в вузе чередуется по чётным/нечётным неделям (уже была готовая логика для этого, писали её раньше для другой задачи — просто переиспользовали). Возвращает список пар: время начала и конца, предмет, преподаватель, тип занятия (лекция/практика), аудитория.

Если попросить дату дальше следующей недели или из прошлого — вернётся понятная ошибка, а не пустой/непонятный ответ.

### 2.3 Незавершённая задача коллеги — TOTP

В репозитории появилась миграция базы данных под двухфакторную защиту QR-кода (чтобы код нельзя было переслать скриншотом другому студенту), но самого кода для этой функции ещё нет — добавлена только структура таблиц. Нужно состыковаться с автором, доделать или пока отложить.

## Часть 3. Сервер и HTTPS

Отдельно занимались переводом сайта на защищённое соединение (https). Ушло много времени на поиск причины, почему сайт был недоступен снаружи — в итоге причина оказалась в особенностях сетевой настройки самого сервера (проброс портов через сторонний туннель), а не в коде проекта. Сейчас сайт уже открывается по https, донастройка "красивого" сертификата без предупреждений браузера продолжается отдельно с администратором сервера.
